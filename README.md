# QR Menu & Ordering — Customer Web App

Mobile-first, fully responsive customer-facing web app for scanning a table QR
code, browsing the restaurant's live menu, and placing orders. Built with
Next.js 14 + Firebase (Firestore for data, Storage for images).

It is the customer side of the desktop **Restaurant POS** system. The POS syncs
restaurant info, menu (with pictures), and table/live-bill status to Firebase;
this app reads the same data in real time so both software and the customer
phone always show the same menu, prices, and bill.

## How a customer orders

1. Customer scans the QR code at their table.
2. The app resolves the restaurant and table from the QR URL (`/t/<restaurantId>/<tableToken>`).
3. If the table is **occupied and the bill is not yet paid**, the customer sees a
   **"Please wait"** screen — they cannot order.
4. When the POS owner/manager completes payment and frees the table, the app
   unlocks automatically (real-time) and the customer can browse + order.
5. New orders pop up in the POS so the owner/manager can **confirm** (accept) or
   reject them. Order status is shown back to the customer in real time.

## QR URL format

Generated by the POS as:

```
https://<your-deployed-domain>/t/<restaurantId>/<tableToken>
```

Example:

```
https://my-menu.vercel.app/t/a1b2c3d4e5f6a1b2/3f9a1c2b-0001-4f3e-8d9a-123456789abc
```

## Environment variables

Set these (in `.env.local` locally, or as Vercel Environment Variables):

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_FIREBASE_API_KEY` | Firebase Web API key |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | `your-project.firebaseapp.com` |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | Firebase project ID (must match POS) |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | `your-project.appspot.com` |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | From Firebase console |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | From Firebase console |

## Local development

```bash
npm install
cp .env.example .env.local   # fill in your Firebase values
npm run dev
```

## Production build

```bash
npm run build
npm start
```

## Firestore rules

Apply `firestore.rules` in the Firebase console (Firestore → Rules). They allow
public reads for the menu/tables and public order creation, while authenticated
POS writes manage menu, table status, and order acceptance/rejection.

## Deploy to Vercel

1. Push this repo to GitHub.
2. In Vercel: **Add New Project → Import** this repo.
3. Add the environment variables above (Production).
4. Deploy. The app's public URL is the domain to paste into the POS
   **QR Ordering → QR Menu Website URL** field.
